## 发现一:M0 解锁了 vanilla 存量预算栈(因果,强证据)

基线 cost=0 → 警告带/子 agent 保留从未触发过。实验中(10/10 run cost 非 0)预算反馈回路真实闭环:

- **警告带 → agent 自主收尾**:smoke-005 的 root 在花到 87% 时主动调用 stop_agent,理由原文 *"Budget at 87% — wrapping up scan; auth not cracked, mass-assignment/IDOR remain open needs_follow_up"*(strix.log 19:37:24)
- **子 agent 预算保留(90%)→ 强制让位**:C-005 和 C-055 各有 **2 个子 agent 在 $0.63–0.65 处被保留栈停掉**("stopping this sub-agent so the root agent can finish the scan"),root 得以收尾出报告;两 run 仍 completed 且 C-055 拿到 FLAG
- B-005/B-010 的 root 也收到过 70% 档注入(花费越过 $0.49),基线的 root 永远收不到

## 发现二:规则真实质量(shadow 模式诚实测量)

`reporting_spawn` 共 **8 次命中**,按 agent 身份判定:3 次真阳性(smoke "API Docs Disclosure Reporting Agent" $0.064 / C-010 "XSS Reporting Agent" / C-055 "SQLi Validation & Reporting Agent"),**4–5 次误报**——攻击型 agent 的任务文本含"…并提交报告"措辞即命中(如 C-005 "JWT Cracking & Forgery Agent" $0.194、"Login Brute-Force & SQLi Agent" $0.178)。

**校准教训**:在 13 条基线任务文本上校准时是 1 命中 0 误报,但运行时模型新生成的任务措辞分布远宽于校准集 → 实际误报率 ~50%。规则 v1 的窄正则对静态文本有效,对生成文本不够。

其余规则 **0 触发**:dedup(0.80)/并发 cap(4)/预算地板(0.90)/个体成本天花板($0.21)——这 3 题的自然行为未达阈值(C-005 的 Recon 花到 $0.210,距 $0.21 天花板一步之遥)。无证据 ≠ 无效,只说明这组任务触不到。

## 发现三:enforce 拒绝的运行时行为(拒绝 → 自适应,零中断)

3 次 deny 全部来自 `reporting_spawn`,拒绝后 root 均在 **~35 秒内**按返回的 reason/suggestion 自适应:

- C-055 23:10:52 deny "SQLi & Auth Bypass Agent"(任务文本 4349 字符命中报告措辞)→ 23:11:25 **同名、任务改写为 3378 字符**重新 spawn → 放行,跑了 25 请求/$0.130
- C-010 23:34:26 deny "XSS Validation Agent"(3913 字符)→ 36 秒后改 spawn "XSS Payload Crafter"(2757 字符)→ 放行
- C-010 23:46:52 deny "XSS Reporting Agent"($0.43 时点,扫描临近结束)→ 未再 spawn,1.9 分钟后正常收尾

10/10 run status=completed,无一次因拒绝中断。C-010 比 C-010 少 1 个 agent(-65 请求,-19% 成本)是拒绝的直接后果;C-005 两次配置成本差(-10.7%)**不含任何拒绝**(enforce 下 4 次 spawn 全放行)—— illustrating n=1 方差幅度。

## 局限(诚实声明)

1. **n=1/格**:B-055 $0.400 vs 基线-055 $0.90 说明同任务跨 run 方差 ≥±40%;跨配置聚合差异(B -39% vs 基线)中相当部分是方差,不可全部归功处理效应。**可归因的是事件级证据**(预算栈触发、拒绝→自适应、C-010 的 agent 减员),不是聚合数字。
2. B 不是无处理对照(预算反馈被解锁是 M0 的一部分)。
3. 4 条规则未触发,无质量数据。
4. 成本为目录价折算,非中转站实扣(待后台核对)。
